PocketDropPrivacy & connection details

Your devices. Your files.

Updated November 7, 2026 · PocketDrop 0.10.19

Files and local storage

PocketDrop transfers only files selected by the user. Incoming phone and PC files stream into a real computer folder selected through Chrome’s folder picker. Completed files in that folder are ordinary readable files and remain there independently of the extension. Name collisions receive a numbered filename rather than replacing an existing file.

Some computer-to-phone files and phone recovery copies use encrypted browser storage until they are saved or deleted. Files queued for Pro transfers can remain as references to the original selected file instead of creating another PocketDrop copy. PocketDrop stores the selected folder handle, transfer metadata, completion receipts, preferences, and unfinished save-job information locally. Clearing browser data or uninstalling the extension can remove browser-stored files, metadata, and the locally saved recovery key.

Chrome may create temporary staging or decrypted export data while writing or downloading a file. PocketDrop removes its temporary data after completion, failure, or cancellation. Downloaded files and files already committed to a chosen folder are not deleted by removing an entry from PocketDrop.

Connections and pairing

After the user starts pairing, PocketDrop contacts PeerJS Cloud at 0.peerjs.com for signaling and Google STUN to help the paired devices establish a WebRTC connection. These providers can receive IP addresses, random connection identifiers, connection descriptions, and timing metadata. File contents are protected in transit by WebRTC transport encryption plus PocketDrop’s application encryption.

The private pairing credential is carried in the QR-link fragment and is not included in the phone webpage’s HTTP request. Anyone holding an unexpired pairing code may attempt to connect, so it must be kept private. Free phone pairings expire after one hour. Pro pairings can remain valid for up to 24 hours. Disconnecting ends the session.

PocketDrop does not configure a TURN file relay. Some workplace, school, guest, VPN, firewall, carrier, or restricted networks may prevent a connection. Internet access is required for pairing, and connection speed depends on the user’s devices and network.

Free and Pro transfers

The Free plan supports phone-to-computer and computer-to-phone transfers up to 500 MB per file. PocketDrop Pro supports files up to 10 GB, private PC-to-PC transfers, different-network connection attempts, and session-only transfer resume while the same pairing remains active.

For PC-to-PC transfers, both computers must use PocketDrop and choose receiving folders. One computer creates a private connection code and the other pastes it into the extension. Explicit Disconnect, Cancel, expiry, browser restart, or extension reload ends session-only recovery. Original files selected for sending are not deleted.

Payment and licence verification

PocketDrop Pro is a one-time lifetime-access purchase processed by Paddle on the PocketDrop website. Card details are entered in Paddle’s checkout and are not sent to the extension or PocketDrop licensing service.

The extension creates a private recovery key and stores it locally in chrome.storage.local. A SHA-256 hash of that key is attached to checkout. The live PocketDrop licensing endpoint receives the recovery key over HTTPS when checking or restoring access, hashes it, and returns only whether the licence is pending, active, or revoked. The licensing database stores the hash, Paddle transaction and customer identifiers, price, payment-event timestamps, and refund or dispute status. Transferred files are never sent to the licensing endpoint.

Keep the recovery key private. Anyone with an active key can restore its Pro access in another supported browser. Approved full refunds and chargebacks revoke access; archiving a checkout discount does not revoke an already completed purchase.

Extension permissions

offscreen keeps user-started transfers and save tasks running when the popup closes. downloads saves a browser-stored file only after the user requests it and checks only downloads started by PocketDrop. storage keeps PocketDrop’s save-job state, receipts, preferences, and recovery key locally. Folder handles and encrypted browser file data use local IndexedDB.

Host access to https://0.peerjs.com/* is used only for connection signaling. Host access to the live PocketDrop licensing Worker is used only for Pro activation and recovery-key checks. The extension requests no access to browsing history, all websites, camera, microphone, contacts, or Chrome sync storage. The phone’s normal camera application scans the QR code outside the extension.

Control, retention, and deletion

Transfers begin only after the user pairs a device and chooses files. The toolbar badge indicates an active session or transfer. Keep Chrome and the phone page open as instructed; closing the extension popup alone does not stop a user-started transfer. Select Disconnect to end the connection.

Files saved in a selected computer folder or downloaded to a phone remain until the user deletes them with the operating system. Browser recovery copies remain until deleted or browser storage is cleared. PocketDrop has no cloud backup for transferred files. Confirm important files were saved successfully before deleting recovery copies.

Security scope and support

PocketDrop uses WebRTC transport encryption, AES-256-GCM application encryption, HMAC-SHA-256 pairing authentication, HKDF-SHA-256 session keys, ordered message counters, and SHA-256 integrity checks. It is unaudited software and cannot protect files on an unlocked or compromised endpoint.
